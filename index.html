02 ・ 置く

S3なんでも置ける倉庫

画像・動画・PDF・CSV・ログ…どんなファイルも保存できるネット上のフォルダ。EC2が「動く場所」なら、S3は「置く場所」です。

中身の構造

my-awesome-bucket ← バケット
├── images/
│   └── neko.jpg  ← オブジェクト
└── pdf/
    └── catalog.pdf

フォルダに見えるのは、ファイル名に「/」を入れて階層っぽく見せているだけです。

ライフサイクルで自動整理

0日保存標準ストレージ
30安い棚へあまり使わない
データを移動
90自動で削除古いログなどを
片付け

「バージョニング」を有効にすると、上書きしても過去のファイルを残せます。

ここがすごい ／ 使い道

消えない（高耐久）どこからでも安いURLで共有 画像・CSS置き場静的サイト公開バックアップ・ログ
まとめ何かを置いてあるところは、だいたいS3。

04 ・ 守る

IAM入退室管理・通行証

Identity and Access Management。日本では「アイアム」と呼ばれます。AWSの鍵と通行証をまとめて管理する仕組みです。

誰がユーザー・サービス
×
どこにEC2・S3・RDS…
×
どこまで読むだけ／編集OK／削除NG

4つの部品

USERユーザー使う人のID
GROUPグループユーザーをまとめる箱
POLICYポリシーできることのルール
ROLEロールサービスに渡す仮の身分証

ポリシーの中身（ポリシーAの例）

{
  "Effect": "Allow",
  "Action": "s3:GetObject",
  "Resource":
    "arn:aws:s3:::my-bucket/reports/*"
}
初心者がやりがちなNG
  • 全員に AdministratorAccess を付ける
  • よく分からず s3:*（全権限）と書く
  • アクセスキーの流出に気づかない
まとめAWSは高性能で破壊力もある道具。最初にIAMを整えるのが大人のたしなみ。
05 ・ 見張る

CloudWatch監視カメラ＆健康診断

「サーバー落ちてない？」「CPU使いすぎてない？」をずっと見守り、異常があれば知らせてくれる見張り番です。

主な機能

METRICSメトリクス数値で見る
ALARMアラーム条件で通知
LOGSログエラーを検索
DASHBOARDダッシュボードグラフで共有

EventBridge（旧CloudWatch Events）と組み合わせると「毎月1日にバッチ起動」なども自動化できます。

あるある

  • ログが無限に貯まって料金が増える → 保存期間を設定
06 ・ 動かす（サーバーレス）

Lambda呼ばれた時だけ働くアルバイト

サーバーを用意せず、コードだけ置いておけば「何かが起きた時」に自動で実行されます。サーバーは裏にありますが、管理はAWSにおまかせ。

料金のかかり方（1日のイメージ）

EC2
ずっと課金
Lambda
動いた瞬間だけ
0時6時12時18時24時

実行時間 × リクエスト回数で課金（ミリ秒単位）。月100万リクエストまでは無料枠あり。「たまにしか動かない処理」ほどお得。

よく組み合わせる仲間

S3：アップロードで起動API Gateway：API化EventBridge：定期実行DynamoDB：保存先Step Functions：手順を管理
ここ気をつけて
  • 1回の実行は最大15分まで。長い処理は分割を
  • タイムアウト設定ミスで処理が途中で落ちる
  • ライブラリが多いとZIPが大きくなる → レイヤー機能で分離

定番の組み合わせ：S3 ＋ CloudFront

静的サイトをS3に置くCloudFront経由で高速配信HTTPS・独自ドメインOKOACでS3への直アクセスを禁止

料金は転送量とリクエスト数の従量課金。無料枠（毎月1TBの転送まで）があるので、小〜中規模ならまず無料で試せます。

注意点
  • キャッシュが効いて古い内容が出続ける → キャッシュ無効化（Invalidation）
  • HTTPSには証明書が必要 → ACMで無料発行
  • 設定項目は多いが、S3＋デフォルト設定なら最小限で始められる
08 ・ 案内する

Route 53名前から住所を教える案内所

AWSのDNSサービス。人が読める「ドメイン名」を、コンピューターが分かる「IPアドレス」に変換します。

「レコード」で行き先を決める

Aドメイン → IPアドレスexample.com → 13.114.123.11
CNAME別名へ転送www.example.com → example.com
MXメールサーバーの指定メールの届け先
TXT認証情報などSPF / DKIM / Search Console

できること

ドメイン取得・更新名前解決ヘルスチェック障害時に別サーバーへ切替S3・CloudFront・EC2と連携

料金の目安

ホストゾーン1つ 約0.5ドル/月 ＋ 問い合わせ数に応じた従量課金。1サイト程度なら月数十円〜数百円。

鉄板構成ファイルはS3 → 配信はCloudFront → ドメインはRoute 53。これで「https://自分のドメイン」のサイトが完成。

10 ・ つなぐ（土台）

VPC自分専用の土地

Virtual Private Cloud。AWSの中に作る自分だけのネットワーク空間です。EC2やRDSはこの中に置きます。

どんな時に意識する？

EC2起動時に、どのVPCに置くかを選ぶ
RDS非公開にしたいならプライベートサブネットへ
LambdaDBに接続するなら同じVPCにいる必要あり
よくあるハマりどころ
  • 全部非公開にして外と通信できない
  • セキュリティ設定が厳しすぎて何もつながらない
  • 最初はAWSが用意している「デフォルトVPC」で感覚をつかむのもアリ
11 ・ 振り分ける

ELBアクセスの交通整理員

Elastic Load Balancing。押し寄せたアクセスを複数のEC2に振り分け、1台にアクセスが集中してパンクするのを防ぎます。

3つの種類

ALB ・ まずはこれApplication Load BalancerWebアプリ向け。Webサービスなら8割これでOK
NLBNetwork Load Balancer超高速。ミリ秒が命のTCP通信向け
CLB ・ 非推奨Classic Load Balancer昔からあるタイプ。古い構成で見かける
気をつけるポイント
  • HTTPS化はELBで（証明書はACMから）
  • セキュリティグループの設定漏れで全ブロック
  • DNS名が *.elb.amazonaws.com になるので独自ドメインはRoute 53と連携
鉄板パターンサーバーを増やす ＝ ELBを入れる。Auto ScalingでEC2を2台→3台に増やしても、URLはそのまま。

# design.md（Kiroが出力した設計のイメージ）

## 構成
- 静的ファイルは S3 バケットに配置
- CloudFront で配信、OAC でS3を非公開に
- 独自ドメインは Route 53、証明書は ACM
- デプロイ用に最小権限の IAM ロール を作成
- エラー率を CloudWatch アラームで監視

黄色の単語がすべて分かれば、AIの提案が妥当かを自分で判断できます。

AIに任せるときのチェックポイント
  • IAMポリシーが *（全権限）になっていないか
  • RDSやS3が意図せず公開されていないか
  • 作ったEC2・RDSを起動しっぱなしにしていないか
